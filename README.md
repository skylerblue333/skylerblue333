## Engineering principles

1. **Describe the code that exists.** Prototype, experiment, archive, and production candidate are different statuses.
2. **Prefer clear boundaries.** APIs, identity, persistence, messaging, clients, and infrastructure should have explicit responsibilities.
3. **Use proven foundations responsibly.** Verify licenses, preserve attribution, and document adaptations.
4. **Validate before making claims.** Tests, builds, dependency review, deployment evidence, and operational checks matter more than repository count.
5. **Consolidate useful work.** Reduce duplication and move mature capabilities behind maintainable interfaces when the evidence supports it.

## Working with the repositories

```bash
git clone https://github.com/skylerblue333/REPOSITORY-NAME.git
cd REPOSITORY-NAME
```

Each repository is authoritative for its own setup, dependencies, license, and validation commands. Before contributing, read its README, use its documented toolchain, run the available checks, keep credentials out of commits, and document behavior changes.

The profile repository also contains a lightweight GitHub Actions workflow for documentation and secret-guard checks. A green workflow is useful validation, but it is not a production-readiness certification.
