## How I work

1. **Start with the code.** Read the repository, its scripts, dependencies, workflows, and documentation before describing it.
2. **Separate ambition from status.** A prototype, experiment, archive, release candidate, and production service are different things.
3. **Prefer boundaries over sprawl.** APIs, identity, persistence, messaging, clients, and infrastructure should have clear responsibilities.
4. **Use open source responsibly.** Check licenses, retain attribution, and document adaptations.
5. **Validate the claim.** Tests, builds, dependency review, deployment evidence, and operational checks matter more than lines of code.
6. **Consolidate what earns it.** Mature capabilities should move toward maintainable interfaces instead of multiplying duplicate systems.

## Maturity and transparency

This profile intentionally does **not** claim that the portfolio represents current revenue, paying customers, production deployment, security certification, or guaranteed uptime. Each repository is its own source of truth for setup, scope, dependencies, license, and validation status.

The profile repository includes a lightweight GitHub Actions workflow for documentation and secret-guard checks. A green workflow is useful evidence for that workflow; it is not a blanket production-readiness certification for the portfolio.
